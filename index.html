How to use this

Start at the top. The first pass takes about twenty minutes and everything after that is a few minutes a week.

First run — do these in order

Each step feeds the next, so skipping one leaves the pages after it empty
  1. Add your accounts. Settings → Accounts. One entry per bank account and credit card you'll import from. Name them the way you think of them, not the way the bank does.
  2. Import a statement. Import → Upload file. A PDF statement works directly; a CSV or Excel export is more reliable if your bank offers one. Get three to six months in. You'll be shown the columns found in the file and asked which is the date, which is the description, and which holds the amounts — banks all label these differently, so nothing is assumed.
  3. Fix the categories. Ledger → set Uncategorised only to Yes. Tap any category cell to set it, and leave the "apply to everything matching" box ticked. Each one you set writes a rule that files every future import automatically, so this is a shrinking job, not a recurring one.
  4. Log what repeats. Recurring → add salary, rent, school fees, loan instalments, subscriptions. The Recurring page also flags charges that appear every month but aren't logged yet — adopt the real ones.
  5. Build the balance sheet. Balance sheet → add every asset and liability. Give each asset an expected return, and tick counts toward independence for anything you'd actually draw on. Your home and car usually shouldn't be ticked; a brokerage account should.
  6. Set up the lumpy things. Targets → add a fund for each cost that arrives in a lump: rent cheques, school terms, insurance, visa renewals. This is the step people skip and it's the one that makes the projection trustworthy.
  7. Read the plan. Overview and 5-year plan will now be populated. Save a snapshot on the Balance sheet so the net worth chart has a starting point.

The rhythm after that

Open the app and the catch-up prompt tells you which of these is actually due
Weekly · 5 minutes

Import the last week's transactions. Clear anything uncategorised. Glance at Targets to see if a category is running hot.

Monthly · 15 minutes

Post due recurring items. Set aside into each fund. Update asset values on the Balance sheet and save a snapshot.

Quarterly · 30 minutes

Revisit expected returns and targets. Run the payoff simulator. Check whether the crossing date moved and why.

What each page is for

Overview

Your standing right now. The independence horizon is the strip of sixty bars — one per month — showing what share of your living costs safe withdrawals from invested assets would cover. Where it crosses 100% is the date the money covers you. Below it, the insight panel reads your actual transactions and reports what it finds rather than offering generic advice.

Ledger

Every transaction, filterable by text, category, account, type and date. Export the filtered view as CSV any time. Tapping a category cell is the fastest way to teach the app your merchants.

Import

Three routes in. Upload takes a PDF, CSV or Excel statement. A PDF is read directly — the text is pulled off the pages, the debit and credit columns are located so each amount gets the right sign, and running balances and reference numbers are discarded; you see the extracted text and can correct it before anything is added. A spreadsheet asks you to map the columns instead. Paste takes rows copied from a PDF or online banking and picks out the date, description and amount, ignoring running balances. Manual is for cash and anything the bank feed misses. Duplicates are detected on date, amount and description, so re-importing an overlapping file is safe.

Recurring

Fixed commitments that post themselves. Press Post due items and everything outstanding is written to the ledger. These form the fixed base of your plan.

Targets

Two halves. Sinking funds for lumpy costs — set the amount and the date and the monthly figure is worked out. Monthly targets put a ceiling on everyday categories; the pale marker on each bar shows where you'd be if the month were spent evenly.

Balance sheet

Assets against liabilities, plus the debt payoff simulator: minimum payments versus avalanche versus snowball, with a slider for extra payment showing months and interest saved. Save a snapshot each month to build the net worth trend.

5-year plan

Sixty months projected from your real savings rate and balance sheet, across three scenarios, with dials for extra saving, spending cuts, return assumptions and extra debt payment. The levers panel answers the practical question: trim each top category by a fifth and here is how many months earlier you cross.

How the numbers are worked out

Worth knowing, so you can tell a real change from an artefact
  • The baseline is the average of your last six complete months. The current month is excluded because it's still running and would drag the average down.
  • Smoothing. A fund marked smoothed removes its category's lumpy real payments from that average and substitutes a steady monthly figure. A single annual rent cheque inside a six-month window otherwise doubles your apparent housing cost.
  • Steady versus catch-up. Funds show two numbers. Steady is the true ongoing cost (48,000 termly is 12,000 a month). Catch-up is what to set aside now if you're behind. Only the steady figure feeds the plan — being behind shouldn't make your long-term outlook look worse than it is.
  • Coverage is invested assets multiplied by your safe withdrawal rate, divided by twelve, against your monthly outgoings. At 4%, a portfolio of 300× your monthly costs covers them indefinitely. Change the rate in Settings if you disagree with 4%.
  • Loan payments categorised as Loan payment are stripped out of projected spending and handled by the liabilities schedule instead, so they're never counted twice. Don't also log them as a recurring expense.
  • Freed payments roll over. When a debt clears, its monthly payment becomes available to the next one, in both the payoff simulator and the projection.

Things that trip people up

  • Moving money isn't spending. Anything between your own accounts should be a Transfer, not an expense, or your spending will look far worse than it is.
  • Credit card payments are transfers too. The spending was recorded when you used the card. Categorise the repayment as Credit card payment.
  • Don't tick "counts toward independence" on your home. You can't spend it without selling it. The same goes for your car and, usually, business equity.
  • A scanned PDF cannot be read. If the statement is a photograph or scan rather than a real text PDF, no text can be extracted. Export a CSV from online banking, or copy the rows into the Paste tab.
  • Three months of data is the minimum before the baseline means anything. Six is better.
  • Expected returns are your assumption, not a forecast. Use the Conservative scenario as your working plan and treat the Aggressive one as upside.

Turning on Microsoft sign-in

If the gate says sign-in is unavailable, one of the first two is the reason
  • Open it in its own browser tab. Not in a preview pane, artifact viewer, or any embedded frame. Microsoft will not run a sign-in redirect inside an iframe whatever the app registration says. The connection check names the parent page when it detects this.
  • It must be served over https. Opening the file from disk will never work — Microsoft refuses a file:// origin. Put it on GitHub Pages like your other tools.
  • Sign-in uses a full-page redirect. Pressing the button sends you to Microsoft and brings you back here — the same flow the Delivery Tracker uses. No popup is involved, so popup blockers and browser privacy settings cannot interfere.
  • If you saw "user cancelled" or "blocked inside a popup" on an older build, that was the popup flow. Microsoft's login page sends a Cross-Origin-Opener-Policy header that severs the link back to the window that opened it, so the library lost track of its own popup and reported it as cancelled. Version 1.7.0 removed popups entirely.
  • If you see "interaction is currently in progress", a previous attempt was interrupted and left a lock in browser storage. The app clears stale locks on every load and retries once by itself; if it still complains, press Reset sign-in state in the error box or the connection check. That wipes the cached sign-in and reloads, and you sign in fresh.
  • If the library still will not load, put your own copy next to this page. Upload msal-browser.min.js (version 2.38.3) into the same folder as this file — it is the last source the app tries, and nothing on a network can block a file you serve yourself. Edge InPrivate with strict tracking prevention is a common culprit; a normal window usually works.
  • Register the redirect URI. Entra admin centre → App registrations → your app → Authentication → Add a platform → Single-page application. Paste the exact URL shown in the connection check, including the trailing slash. A mismatch of even one character fails, and with the redirect flow the failure appears as an AADSTS50011 message from Microsoft before you get back here.
  • Consent the permissions. Same app → API permissions → Microsoft Graph → Delegated → add User.Read and Files.ReadWrite.All, then grant consent.
  • Then reload the page and sign in. The folder and file are created on first save; you do not need to make them yourself.

Locking it to one account

The page is set to ahmed@core-velocity.com — but a page cannot enforce that on its own
  • In the page. Near the top of the file, CONFIG.allowedUser holds the address. Any other account that signs in is rejected and told why. This is a convenience guard: it keeps the wrong account from quietly syncing into the wrong OneDrive.
  • In Entra — this is the real lock. Enterprise applications → your app → Properties → set Assignment required to Yes. Then Users and groups → assign only your account. Now Microsoft itself refuses a token to anyone else, whatever the page says.
  • Why both. Anyone who views the page source can change a line of JavaScript. Nobody can change what Entra will issue a token for. Do the second step and the first becomes a courtesy message rather than a security control.
  • Your data is separately safe. The file sits in your own OneDrive, so another account would reach their own empty file, not yours.

Sync, reminders and your data

  • Where it lives. One JSON file in your own OneDrive. Changes save a moment after you make them and merge across devices — the most recently edited version of each record wins, and deletions are respected.
  • Hosting. Wherever you host this page, add that exact URL as a SPA redirect URI on the Azure app registration, and consent to Files.ReadWrite.All. Until then, Work offline on this device runs everything locally.
  • Reminders appear when you open the app. A single HTML file has no server, so nothing can reach you while it's closed. On a phone, add the page to your home screen and open it once a day.
  • Backups. Settings → Download backup writes the whole file to disk. Restoring merges rather than overwrites, so nothing is lost.
